Figure 3-8 volume-operator comparison reproducibility folder

See README.md for the full reproducibility guide, including run commands,
literature references, equations, method-file mapping, expected results, and
known limitations.

Goal
----

This folder is organized so a reader can recompute the Figure 3-8 numerical
curves before plotting the PNG panels. The plotting script reads only generated
*_all_methods_result.csv files inside the case folders.

The equations, literature references, and callable functions used by the CSV
generators are kept directly in the method-specific top-level files:

- plic_pl_1998_1999.py
- evrard_2023.py
- xie_xiao_2017.py
- strobl_2016.py
- present_quadric_patch_2026.py

Those files are intentionally kept inside this figure folder, next to the
scripts, so the computational assumptions, equations, and method call path are
visible without searching through the manuscript or a hidden shared helper.

The static geometry meshes are generated by top-level geometry files in this
same folder:

- sphere_mesh.py
- cylinder_mesh.py
- paraboloid_mesh.py
- hyperboloid_mesh.py
- parabolic_cylinder_mesh.py
- hyperbolic_cylinder_mesh.py

Each geometry file can be run directly, for example:

python cylinder_mesh.py --level 1 --out cylinder_level1.msh

The static case scripts call these geometry files through their ``generate_mesh``
functions before computing the method curves.

Full recomputation
------------------

Run from this folder:

python RUN_RECOMPUTE_FIGURE_3_8.py

or:

python recompute_all_cases.py

On macOS, you can also double-click:

RUN_RECOMPUTE_FIGURE_3_8.command

This command deletes old generated CSV/TXT/PNG/PDF files first. It then
recomputes the numerical CSVs from the bundled method scripts, local meshes, and
local saved simulation states before redrawing the plots. After a successful
run, it validates the expected CSV row counts, validates the generated PNG/PDF
outputs, copies the PDF to the rebuttal package, and removes temporary _work and
__pycache__ folders. The terminal output shows case progress, generated PNG/PDF
outputs, mesh-preview outputs, and timing summaries for the five method columns. In the dynamic cases,
PL and present-method values are loaded from saved full-solver summaries; the
Evrard-type, THINC/QQ-type, and Strobl-type comparison columns are recomputed
from the saved surface meshes. The macOS .command launcher also writes
recompute_all_cases_terminal.log in this folder. Use Figure_3-8_VolumeOperatorComparison.py
only when you intentionally want plot-only regeneration from already generated
CSV files.

The scripts first check the Python runtime. If your current Python is missing a
needed package, the bootstrap tries a dependency-ready Python such as the bundled
Codex Python. If none is found, it installs the packages listed in
requirements.txt into the local _python_deps folder. This keeps the setup local
to this figure folder and avoids modifying global site-packages.

For a manual setup, use Python 3.12 or 3.13 when possible:

python -m pip install -r requirements.txt

The Strobl comparison uses the overlap package. Some very new Python versions
may not yet have prebuilt overlap wheels, so Python 3.12/3.13 is the safer
choice for independent reproduction.

This runs:

1. recompute_all_static_cases.py
2. cube2sphere/cube2sphere_all_methods.py
3. droplet_oscillation/droplet_oscillation_all_methods.py
4. Figure_3-8_VolumeOperatorComparison.py
5. mesh_plot.py

The two dynamic numerical curves can be slow because they recompute comparison
volume models over 1000 and 2000 saved mesh states. The mesh-preview folder,
however, intentionally shows only the initial dynamic mesh t0 for each method.

The raw source artifacts are listed in source_manifest.txt. The generated
result CSV files in the case folders are outputs and are deleted/rewritten by
recompute_all_cases.py.

Static cases
------------

The six static geometry folders are:

- sphere
- cylinder
- paraboloid
- hyperboloid
- parabolic_cylinder
- hyperbolic_cylinder

Each static geometry folder contains:

- *_all_methods.py
- *_all_methods_result.txt
- *_all_methods_result.csv, generated by recomputation
- method folders listed below

Each method folder contains its own Python runner and generated method-specific
CSV/TXT outputs:

- PLIC_PL
- Evrard_type_paraboloid
- THINC_QQ
- Strobl_sphere_overlap
- Present_quadric_patch

Example:

cd sphere/PLIC_PL
python PLIC_PL.py

That uses sphere_all_methods_result.csv if it already exists, or recomputes the
parent sphere_all_methods.py output if it is missing, and then extracts the PLIC
/ PL column into PLIC_PL_result.csv and PLIC_PL_result.txt.

Dynamic cases
-------------

The dynamic folders are:

- cube2sphere
- droplet_oscillation

Each dynamic folder has the same five method subfolders. The dynamic
*_all_methods.py scripts use the local copies in source_data/, so the Figure 3-8
folder can be rerun without copying files from Figure_3-3 or Figure_3-7. The PL
and present quadric-patch curves are read from the local simulation-summary
copies. The Evrard-type, THINC/QQ-type, and Strobl-type comparison curves are
recomputed from the local saved surface mesh states.

Example:

cd cube2sphere
python cube2sphere_all_methods.py

This writes cube2sphere_all_methods_result.csv and method-specific result files.
The per-method dynamic scripts behave the same way as the static method scripts:
they extract their method column from the generated parent CSV when available,
and recompute the parent dynamic CSV only if that parent output is missing.

Mesh previews
-------------

The folder mesh/ is generated by:

python mesh_plot.py

It is also regenerated automatically by:

python recompute_all_cases.py

The mesh folder contains method-labeled PNGs for the mesh inputs behind Figure
3-8: four refinement levels for each static panel 3-8a through 3-8f and only
the initial saved dynamic state t0 for 3-8g and 3-8h. Each panel/method
combination has its own PNG. Methods that use the same surface mesh are labeled
separately so this is explicit; the Evrard paraboloid forward-operator panel
shows its background tetrahedral mesh; and the Strobl comparison shows its
fitted-sphere hexahedral overlap grid. The file mesh/manifest.csv records the
panel, case, method, source mesh, level or iteration, point/cell counts, and PNG
filename for each preview. This makes it possible to inspect the geometric
input behind the regenerated plots, not only the plotted CSV data.

Plotting
--------

After the result CSVs exist, run:

python Figure_3-8_VolumeOperatorComparison.py

This redraws:

- Figure_3-8a.png
- Figure_3-8b.png
- Figure_3-8c.png
- Figure_3-8d.png
- Figure_3-8e.png
- Figure_3-8f.png
- Figure_3-8g.png
- Figure_3-8h.png

Important
---------

This folder no longer uses copied plotting CSVs as input. The source inputs are
case scripts, local saved meshes, local simulation-summary files, and bundled
manuscript helper libraries. Existing PNGs are outputs. To verify the figure,
rerun recompute_all_cases.py and then inspect the regenerated PNG/PDF files.
