# 07 — Physics Audit: Synthesis of Verified Findings

> Sources checked: docs_temp/audit/*.md (15 per-item findings files, each with numerical probes run in the `ddg` env against the 2026-07-02 working tree; 6 items adversarially re-verified by a skeptic pass), 02_physics_foundations.md, sources/fundamentals.md, code_map/* | Written 2026-07-02 by physics-audit workflow

**One-paragraph summary.** The single-phase discretisation is verified correct to machine precision (dual closure ≤ 3.1e-17, pairwise antisymmetry exact, `stress_force(mu=0) = -∇p·Vol` to 3.6e-15). The two highest-impact **confirmed** bugs both trace to a single root cause — treating a stored pressure of exactly `0.0` as "phase absent" in the multiphase pressure flux — which injects a non-conservative momentum source (up to 79–86 % of max|F|) into the wave-launch transient of every default `P0=0` oscillating-droplet run and makes results gauge-dependent. The second independent high bug is `dual_volume` in 3D (non-converging ~4 % interior / ~20 % boundary volume error feeding the EOS). A factor-2 bug in the 2D volume-averaged-IC/validation helpers is high severity globally but does not touch the droplet cases. Everything else is medium/low, latent, or a documented design limitation. After the sentinel and dual-volume fixes, the remaining 2D droplet residual (pinned floor 2.3749e-3 / 2.2717e-3) is **O(h) polygon-vs-circle geometry error on the pressure/dual-partition side**, not an operator bug — do not chase the curvature stencil (see §3 and §4).

Per-item detail files live in [`docs_temp/audit/`](audit/). Every claim below carries its item key; read the item file for probe scripts, full outputs, and exact file:line evidence.

## 2. Confirmed bugs, ranked by oscillating-droplet impact

Effort estimates assume the `ddg` env, repo-root cwd, and the regression tests named in each item file.

### 2.1 Zero-pressure sentinel in the multiphase pressure flux — **the** droplet bug
- **Items:** [zero-gauge-pressure](audit/zero-gauge-pressure.md) (high) + [multiphase-momentum](audit/multiphase-momentum.md) (high) — *same root cause, one fix*.
- **Where:** `_phase_pressure` at `ddgclib/operators/multiphase_stress.py:88-91` (`if val == 0.0: return fallback`, while the own-side read at `:142` is raw → asymmetric flux); write side `multiphase.py:547-549` stores 0.0 for absent phases; interface-average filter `multiphase.py:559` (`!= 0.0`).
- **Droplet impact:** direct and default-configuration. `setup_oscillating_droplet` defaults both phases to `P0=0` (`_setup.py:39`), so quiescent vertices store bitwise-0.0 pressures; during the wave-launch transient the sentinel misfires (84–117 per-call misfires in real runs, substituted pressures up to 9.4e3 Pa), erring on force by up to 129 % relative and injecting |ΣF| up to 13.5 N = 86 % of max|F| for ~9–25 steps before self-quenching. Results become P0-dependent when physics forbids it; interface `v.p` diagnostic reports 5.0 instead of 2.5 Pa. Gauge-shifting to P0=1000 restores conservation bitwise — airtight isolation.
- **Fix:** key phase presence on geometry/mass, not the pressure float: in `_phase_pressure` return the stored value unless `dual_vol_phase[k] <= 1e-30` (mirroring the gate `mass_redistribution.py:304-313` already uses — the codebase itself documents this exact trap); same change at `multiphase.py:559`; make absent-phase handling symmetric on both face ends; add a diagnostic counter + corrected comment to the latent skip branch at `multiphase_stress.py:171-177`. Add gauge-offset-invariance + pairwise-antisymmetry regressions on the perturbed P0=0 droplet (probe monkeypatch already verified: restores both to machine precision, 3.7e-15 N).
- **Effort:** ~1–2 h code + ~1 h tests. **Do this first.**

### 2.2 `dual_volume` 3D undercount (non-converging) — the 3D droplet EOS-noise amplifier
- **Item:** [dual-volume-3d](audit/dual-volume-3d.md) (high; skeptic-upheld), corroborated by the side finding in [dual-closure-antisymmetry](audit/dual-closure-antisymmetry.md).
- **Where:** `ddgclib/operators/stress.py:311-372` — v_star fan uses tet barycenters only (no face barycenters, unclosed boundary caps) + silent `continue` on per-edge exceptions at `:367-368`.
- **Droplet impact:** 2D essentially unaffected (machine-exact except O(h²) frozen box corners). 3D directly affected: ρ = m/Vol feeds the EOS with configuration-dependent 1–4 % interior / ~20 % boundary volume errors that *change on every re-Delaunay* while mass stays frozen → misread as compression (spurious dP ~ K·dV/V; ~8 Pa at K_d=800, MPa-scale at stiff water K) — a much larger version of the documented retopo-noise root cause of the 3D blow-up. Conservation diagnostics under-report by 6–14 %.
- **Fix:** for barycentric duals replace the dim==2/3 branches with the exact closed form Vol_i = (1/(dim+1))·Σ_{T∋i}|T| over incident top simplices (validated to 3.4e-15, tiles the domain including boundaries, no exception paths, cheaper); keep v_star only for circumcentric duals; stop silently continuing on exceptions; tighten `test_partition_of_unity` to a refined+jittered mesh at rtol~1e-12 (it currently passes only on the symmetric 9-vertex fixture — 8× outside its own rtol after one refine).
- **Effort:** ~2–4 h code + tests.

### 2.3 One-sided `rho_clip` + zero-gauge presence filters in the EOS layer
- **Item:** [eos-formulas](audit/eos-formulas.md) (medium after skeptic downgrade from high).
- **Where:** `ddgclib/eos/_tait_murnaghan.py:61-66` (clip in `pressure()` only; `density()`/`sound_speed()` unclipped → round-trip broken, dP/dρ silently flat-lined at band edges); `mass_redistribution.py:156,314` inverts saturated pressures through the unclipped `density()`.
- **Droplet impact:** bounded under shipped defaults — in an instrumented 45-step run all ~9/247 pinned pairs were frozen wall-boundary vertices (0 interface); the shipped c_s=5 m/s gives representable windows ~50× the case's dynamic pressure scale. Full interface saturation occurs in `redistribute_mass=False` runs. Pinned wall pressures still enter neighbours' pressure fluxes — a real, persistent, silent thermodynamic inconsistency.
- **Fix:** apply `rho_clip` consistently across pressure/density/sound_speed (or replace silent clipping with a warned/counted diagnostic); floor `IdealGas.density` at 0; fix stale docstrings. (The `!= 0.0` presence filters are fixed by 2.1.)
- **Effort:** ~1–2 h.

### 2.4 Retopology edge cases (`skip_triangulation` mis-tagging; dam-break forwarding; stale-dual bare returns)
- **Item:** [retopo-edge-cases](audit/retopo-edge-cases.md) (medium).
- **Where:** `_integrators_dynamic.py:202-207` (bV-derived boundary tags under `skip_triangulation`), `:136-153` (bare returns), `:360-374` (`skip_triangulation` not forwarded to custom retopologize_fn — dam break runs full Delaunay every step contrary to its own comment).
- **Droplet impact:** oscillating droplets don't hit (a)/(b) (no `boundary_filter`, no forwarded `skip_triangulation`); (c) affects only the 3D droplet's frozen outer-box walls (the documented one-shot |dV/V0|~0.3 artefact). Dam break is the affected production family.
- **Fix:** derive boundary from topology (`boundary_from_simplices`) not filtered bV; forward `skip_triangulation` via the same inspect pattern as `remesh_mode`; replace bare returns with warnings; make `DualVolumeMass` warn on the 1e-30 fallback.
- **Effort:** ~3–5 h across the four sub-fixes. Fix (a) **before or together with** the dam-break forwarding fix, or the 3D dam break inherits the +30 % dual-volume corruption.

### 2.5 Factor-2 in 2D volume-averaged pressure ICs and sanctioned validation metrics
- **Item:** [gravity-bodyforce](audit/gravity-bodyforce.md) (high globally, **zero droplet impact** — droplet/bubble cases never import these helpers; their pressure comes from the EOS).
- **Where:** `ddgclib/analytical/_integrated_comparison.py:161` (`w * P * 2.0 * tri_area` with Dunavant weights already summing to 1) and `_dual_cell_pressure_integral_2d` (`:68-114`, plus an erroneous `if ti+tj>1.0: continue`).
- **Impact:** `volume_averaged_scalar(1) == 2.000000`; `HydrostaticPressure` assigns `v.p = 2P` whenever duals exist (the shipped hydrostatic case order) → ~6g spurious acceleration; worse, a **self-cancellation trap**: `integrated_pressure_error` reports 2.8e-14 (false perfect) on the doubled field and 8.9e+01 (false alarm) on a correct field — the sanctioned 2D metrics are currently untrustworthy.
- **Fix:** delete the `2.0` (both sites), remove the bogus `continue`, fix the `_divergence_theorem.py:279-281` docstring, add `volume_averaged_scalar(1)==1`-with-duals and IC-after-`compute_vd` regressions.
- **Effort:** ~30 min code + ~1 h tests. Cheap and restores trust in validation — do it early even though droplets are unaffected.

### 2.6 `DynamicSimulation.run` kwarg collision

- **Fix:** bind `dudt_kwargs` into the function with `functools.partial` instead of flat-merging into integrator kwargs; forward or delete `params.rho`; fix the crashing docstring; spy-based test. **Effort:** ~1–2 h.

## 3. Cleared suspicions — do NOT re-chase these

Evidence-backed negatives from the audit; each was a live suspicion in debugging_plan.md / code_map flag lists.

1. **The e_ij = −e_ij flip in `_curvatures_heron.py:241,361` ("# WHY???") is NOT a sign bug.** It makes HNdA outward-oriented and cancels *exactly* against the −γ at `multiphase_stress.py:274` (HNdC_ijk verified exactly linear in e_ij; 26/26 vertices inward, |HNdA| = (2/R)·C_i to 1.0000). A self-consistent convention pair — change both or neither. [st-sign-conventions](audit/st-sign-conventions.md)
2. **The default `'integrated'` surface-tension path is label-invariant and correct** in 2D and 3D (inward, Young–Laplace magnitude to 1.0000–1.0006, ΣF ≤ 7e-18); only opt-in `csf_dual` has the orientation bug. [st-sign-conventions](audit/st-sign-conventions.md)
3. **The exact 2D FTC operator IS wired into production** — debugging_plan.md:84 "Tier 2B step 1: replace `hndA_i_interface` with `surface_tension_force_2d`" rests on a false premise: the dispatch has existed since the first multiphase commit (1690ce0). 32/32 interface vertices route through it, 0 through `hndA_i_interface`; dispatch diff bitwise 0.0. No wiring change can move the 2.3749e-3 floor. [tier2b-2d-status](audit/tier2b-2d-status.md)
4. **The pinned 2D droplet floor is NOT curvature-stencil truncation** (contradicting 02_physics_foundations.md:135): the ideal curvature-side imbalance is 4.72e-5 = **2 %** of the floor; ~98 % is pressure-flux/dual-partition chord-vs-arc mismatch, converging at O(h) (p ≈ 1.05–1.10 over 32/64/128 interface vertices). A Tier 2B curvature rewrite can recover at most ~2 %. [curvature-2d-consistency](audit/curvature-2d-consistency.md), [tier2b-2d-status](audit/tier2b-2d-status.md)
5. **The angular-gap 2D interface-neighbour heuristic is bit-identical to exact connectivity** in all production configurations (1600 force evals over 50 steps incl. per-step retopo); mispick requires a locally concave vertex + flag-complex chord, never observed. [curvature-2d-consistency](audit/curvature-2d-consistency.md)
6. **Gravity handling itself is correct**: `stress_acceleration` returns F_stress/m only (by design), cases add `a + g_vec` exactly once per substep (identity to 1.8e-15), never skipped on interface vertices; hydrostatic equilibrium balances to 2.2e-12 through point-value pressure. The 6g probe failure was entirely the factor-2 IC bug (§2.5). [gravity-bodyforce](audit/gravity-bodyforce.md)
7. **Integrator operation ordering is sound for all droplet cases**: symplectic_euler (used by every droplet/bubble case) evaluates forces on duals with 0 moves and 0.0 position drift since `compute_vd`; per-phase pressures recomputed twice inside the retopo before forces. The known 2D droplet validation failure is **not an ordering bug**. Only rk45 (stale stage duals) and euler_adaptive (advective-only CFL) deviate — neither is used by any droplet/bubble case. [integrator-ordering](audit/integrator-ordering.md)
8. **Dual closure, pairwise antisymmetry, and linear-pressure exactness of the single-phase operator hold to machine precision** (≤ 3.1e-17 / ≤ 3.0e-18 / rel ≤ 3.6e-15) on 2D/3D structured and jittered meshes; the only antisymmetry break is 2 boundary–boundary edges on hyperct-native connectivity that vanish under the re-Delaunay pattern `_retopologize` uses. [dual-closure-antisymmetry](audit/dual-closure-antisymmetry.md)
9. **The `norm_sq == 0` short-circuit in `dual_volume` is not a bug** — all 1488 triggers were exactly-coincident points. [dual-volume-3d](audit/dual-volume-3d.md)
10. **The cross-phase skip branch at `multiphase_stress.py:171-177` is latent, not active**: 0 firings in 9 clean scenarios (2D/3D, static/perturbed, pre/post retopo); `_dual_split_2d.py:575-583` guarantees bulk vertices always receive their own phase, so its comment's "bulk-bulk cross-phase" trigger is impossible. It only fires on corrupted interface tags. [multiphase-momentum](audit/multiphase-momentum.md)
11. **Batch-vs-sequential dual construction does not affect droplets**: runtime spy shows droplet cases only ever take the sequential simplex-aware path (batch requires an explicit `backend`, never passed); even under a backend, interior forces/volumes are bit-identical. [batch-vs-sequential-3d](audit/batch-vs-sequential-3d.md)

## 4. Design limitations to respect

- **rk45 stages run on macro-step-frozen duals** (dual cells, dual_vol, `_edge_area_cache`): stage drift up to 1.2e-05 invisible to scipy error control. Documented-vs-code mismatch is in the docstring only. Use `symplectic_euler` for anything dual-sensitive. [integrator-ordering](audit/integrator-ordering.md)
- **euler_adaptive CFL is advective-only** (`dt = clip(0.5·h_min/u_max, 1e-12, dt_max)`, returns `dt_max` when quiescent). `dt_initial` must itself satisfy acoustic/capillary limits. [integrator-ordering](audit/integrator-ordering.md)
- **3D boundary dual faces are approximate** (cap residual median 9–20 % of the closure defect); wall vertices are frozen in all shipped cases so this is inert, but do not build boundary-flux physics on them. [dual-closure-antisymmetry](audit/dual-closure-antisymmetry.md)
- **Boundary dual_vol=0 → `DualVolumeMass` m=1e-30 at retopo (3D batch path)** is intentional; `DualVolumeMass` is setup-time-only per its docstring (`initial_conditions.py:308-309`) and every shipped case complies. Consequence: 3D wall vertices are EOS-pinned to reference pressure and invisible to volume accounting (the documented one-shot |dV/V0|~0.3 artefact). [retopo-edge-cases](audit/retopo-edge-cases.md)
- **The 2D droplet force floor (2.3749e-3 frozen / 2.2717e-3 post-retopo) is O(h) polygon-vs-circle geometry error** of the piecewise-linear interface — the operators are exact on the polygon. Moving it requires a higher-order interface representation (e.g. curved-arc reconstruction, `curvature_2d.py:184-231`) consistent with the discrete pressure flux; it is *not* fixable by any dispatch/stencil change. [tier2b-2d-status](audit/tier2b-2d-status.md)
- **The angular-gap interface heuristic** is motion-robust by design; harden (filter through `interface_nn` when `HC.interface_edges` is fresh) rather than replace. [curvature-2d-consistency](audit/curvature-2d-consistency.md)

## 5. Recommended fix order for the solver-debugging workflow

Ordered by (droplet impact) × (confidence the fix is correct) ÷ effort. Verified monkeypatch fixes exist for #1; #2 has a validated closed-form replacement.

1. **Zero-pressure sentinel** (§2.1) — one small change (`dual_vol_phase[k] > 1e-30` presence gate in `multiphase_stress.py:88-91` + `multiphase.py:559`, symmetric absent-phase handling) removes *both* high-severity droplet bugs; probe-verified to restore gauge invariance and pairwise momentum antisymmetry to machine precision. Add the gauge-invariance + antisymmetry regressions in the same commit.
2. **`dual_volume` 3D exact closed form** (§2.2) — Vol_i = (1/(dim+1))·Σ|T∋i|; unblocks the 3D droplet EOS-noise diagnosis and makes conservation diagnostics honest. Tighten `test_partition_of_unity` simultaneously.
